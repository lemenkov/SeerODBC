SeerODBC 0.3.0 is the first release for **Windows**: 64- and 32-bit drivers, an installer, and DSN setup in the ODBC Data Source Administrator, checked live under Microsoft's own Driver Manager. It also adds **Oracle 8i** (login and queries), reports why a connection failed, and fixes some twenty fetch, bind and protocol bugs found by syncing with seerdb's `PROTOCOL.md`.

**One breaking change:** the command-line client `freeoracle` is now **`seersql`** (#92). Scripts that call it need the new name; its options are unchanged.

### New features

- **Windows support**, 64-bit and 32-bit (#93–#96, #99–#101, #106–#108):
  - **An installer**, `seerodbc-<version>-windows-setup.exe`, carrying both drivers. The 64-bit one goes to `Program Files\SeerODBC` and the 32-bit one to `Program Files (x86)\SeerODBC`, each registered for applications of its bitness (a driver's bitness must match the *application's*: 32-bit Office needs the 32-bit driver). It adds an Apps & features entry and an uninstaller, and `/S` runs silently (#107).
  - **A zip per bitness** for portable or no-admin use, with `register.cmd` and `add-dsn.cmd` (#94, #95).
  - **DSN setup in the ODBC Data Source Administrator**: Add / Configure / Remove a SeerODBC data source in a dialog with a **Test connection** button, which logs in and shows the server's version or its error. The test password is never stored. The same works from PowerShell's `Add-` / `Set-` / `Remove-OdbcDsn` and from `SQLConfigDataSource` (#108).
  - **`selftest.ps1`**, in both the zip and the install: one command that checks registration, DSNs and live queries against your servers (#99).
  - The driver's complete Unicode (`…W`) entry points, which Microsoft's Driver Manager requires: without them the first statement crashed inside `odbc32.dll` (#101).
- **Oracle 8i (8.1.7)**: login and queries, read-only, on the legacy dialect 8i speaks (#83).
- **Why a connect failed**: a failed `SQLConnect` / `SQLDriverConnect` now carries the server's error, for example `ORA-01017` (native error 1017) for a wrong password or `ORA-12514` for an unknown service, instead of a generic one (#89).
- **`EXPIRE_TIME=n`**: TCP keepalive after *n* minutes idle, so a connection dropped by a firewall is detected instead of hanging (#90).
- **`SQL_MAX_*_NAME_LEN`** report the server's identifier limit: 128 from 12.2 on, 30 before (#88).
- **`SQL_DBMS_VER`** reports the server's real release instead of a fixed `11.02.0000` (#75).
- **Log levels**: the driver's log uses DEBUG / INFO / WARNING / ERROR consistently, and every line says it comes from `seerodbc` (#100).
- **A Homebrew formula** for macOS, built and tested in CI (#82).

### Fixes

- **Results over 100 rows that repeat a value across fetch batches failed** with a protocol error, on every server (#77).
- **A call running longer than 30 seconds failed** with an I/O error on plain TCP: the connect timeout was never lifted after login (#68).
- **A long connect descriptor** (a long host or service name) hung the connection (#69).
- **23ai: a CLOB / BLOB read across fetch batches could fail** with a protocol error when the server was slow to send the reply's next fragment (#97).
- **A server error arriving in the middle of a result** (e.g. ORA-00604 on 10g past `open_cursors`) was reported as a protocol error, sometimes with the previous statement's message. Now the real ORA error is reported, for that call only (#85).
- **10g / 11g: warning replies desynchronized the session** (#72).
- **REF CURSOR and implicit-result fetches** failed on 10g–21c when the rows held nested cursors (#76).
- **12c+ objects:** NVARCHAR2 / NCHAR attributes came back garbled and bound wrong (#73); TIMESTAMP WITH (LOCAL) TIME ZONE attributes were sized as plain TIMESTAMP (#79).
- **A TIMESTAMP bind with a zero fraction** matched no rows against `TRUNC(...)` values (#80).
- **A LOB read whose content ran past the reply** returned truncated data silently; it now fails (#74).
- **9i:**
  - **a wrong password connected** instead of being refused (#89);
  - **NCHAR / NVARCHAR2 values** came back corrupted, and characters outside the database charset were lost (#102);
  - ROWID / UROWID columns could not be fetched (#70), and a ROWID column's size was reported as 1 byte (also on 8i), so an application sizing its buffer from it cut the rowid short (#84);
  - queries with 256 or more columns, or that many defines, misdecoded (#71);
  - error messages longer than 64 bytes were cut short (#78).

### Tooling

- **Windows CI**: native MSYS2 builds (MINGW64 and MINGW32) and Fedora MinGW-w64 cross builds on every PR, with an export check (undecorated names, every Unicode entry point, `ConfigDSN`) and zips as artifacts (#95, #96, #101, #106).
- **`release.yml`** builds the Windows zips and the installer for each tag and attaches them to the Release (#95, #107). The installer builds on Linux with Fedora's NSIS (`packaging/windows/make-installer.sh`).
- **Curated in-tree release notes** (this file) are published as each Release's body (#81).
- The tests keep their assertions in optimized builds too (#98).
- `README`, `AGENTS.md` and the roadmap state the project's goal: connect to the database and support its features, not implement every protocol (#91). "Oracle" is kept to nominative mentions, with a non-affiliation note (#92).

### Validation status (honest)

- **Live, full matrix green** (`tests/odbc/run-matrix.sh`, lab servers, on master `becc39f`: this release's code but for the version number):

  | 8i | 9i | 10g | 11g | 18c | 21c | 23ai | 26ai |
  |---|---|---|---|---|---|---|---|
  | 10/0 | 23/0 | 77/0 | 75/0 | 82/0 | 84/0 | 90/0 | 89/0 |

  8i 8.1.7 and 9i 9.2.0.4 run the core-API suites (8i read-only). 10g 10.2.0.5, 11g XE 11.2.0.2, 18c XE, 21c XE 21.3 and 23ai Free run the full ODBC suite, and so does 26ai, with native network encryption required (AES256 + SHA256).
- **Windows, live, under Microsoft's ODBC Driver Manager** on one Windows 11 (26H2) x64 VM, using this release's own artifacts from a `release.yml` dry run:
  - the x64 and the x86 zip each pass `selftest.ps1` **24/0** against 9i, 10g, 11g, 18c, 21c, 23ai and 26ai, by connection string and by DSN;
  - the installer installs silently, both installed drivers pass `selftest -Installed` **22/0**, and it uninstalls leaving no registration, entry or folder;
  - DSNs are created, changed and removed through `Add-` / `Set-` / `Remove-OdbcDsn` (64-bit user and 32-bit system DSNs) and connected through. The Administrator dialog (Add, Test connection, Configure with rename, Remove), in both the 64- and the 32-bit Administrator, was exercised by hand with the build of #108, the same setup code.
  - Zips cross-built on Linux (Fedora MinGW-w64) pass the same tests as the native MSYS2 ones.
- **GitHub CI (public tier):** 11g XE, 21c XE and 23ai Free containers; native and cross Windows builds; macOS.
- **Not validated:** 12.1 / 12.2 / 19c against real servers (12.1's wire level is exercised by capping a 21c session); Windows 10, Windows on ARM, and applications other than the test tools and .NET's `System.Data.Odbc`; the installer on 32-bit Windows.
- **Limitations:** the Windows installer is **not code-signed**, so SmartScreen may warn before it runs. 8i is login and queries only. Connection pooling (DRCP) on 11g is not supported: 11g's pooled server needs a client form SeerODBC does not implement.

### Installing

- **Windows:** run `seerodbc-0.3.0-windows-setup.exe`, or unpack the zip for your application's bitness and run `register.cmd` from an elevated prompt. See `packaging/windows/README.md`.
- **Linux, from source:** `meson setup build && meson compile -C build`, then register `build/src/odbc/libseerodbc.so` (see `packaging/odbcinst.ini.sample`).
- **Fedora:** `packaging/seerodbc.spec` builds from this tag's tarball.
- **macOS:** `packaging/homebrew/seerodbc.rb`, or as Linux with Homebrew's OpenSSL 3 and unixODBC.
