SeerODBC 0.5.0 is an **ODBC conformance and correctness release**. It reworks how values convert in both directions, gets time zones right, and lets you connect the way Oracle's own clients do: **tnsnames.ora aliases** and **Easy Connect**. About thirty bugs are fixed, several of them wrong data that came back with no error.

### Changes you may notice

None of these needs a code change, but an application could see a difference:

- **Time zones:**
  - **TIMESTAMP WITH TIME ZONE** reads as the time it was stored. `10:00 +02:00` is 10:00 in a timestamp struct, and `2026-11-20 10:00:00 +02:00` as text, where both gave the UTC 08:00 with the zone dropped (#359). A region zone (`Europe/Berlin`) stays UTC, and its text says `+00:00`.
  - **The session time zone is set at login**, as OCI sets it. It is `ORA_SDTZ` if set, otherwise the client OS's UTC offset (#358). Before, every session took the server's default zone. This moves `CURRENT_TIMESTAMP`, `LOCALTIMESTAMP` and LOCAL TIME ZONE values to the client's zone, as SQL*Plus shows them.
  - **TIMESTAMP WITH LOCAL TIME ZONE** reads in the session's zone. It read in the database's zone (#358).
- **Transactions:**
  - **Switching autocommit back on commits** the open transaction, as ODBC specifies; it stayed open (#342).
  - **SQLDisconnect refuses with 25000** while a manual-mode transaction is open, on 8i and on 10g and later (#344). 9i's replies don't say whether a transaction is open, so there it disconnects as before.
  - **A refused commit is 40002 on every path.** An autocommit on 9i whose commit failed reported success (#346, #347).
- **Errors where there was silence:**
  - **An attribute number ODBC doesn't define is HY092** on set and get; it was accepted (#373). Asynchronous execution at the connection is HYC00, as on a statement. Standard attributes the driver has no use for are still accepted.
  - **Fetch targets are range-checked:** integer, bit, `SQL_C_NUMERIC`, date and time targets give 22003, 22018 or 01S07 where they used to wrap, truncate or parse text silently (#329, #332, #334).
  - **A number or a date cut short in a character buffer** is 22003, not a shorter value with 01004 (#336).
  - **Interval and GUID targets** convert, or fail, instead of returning the text bytes as success (#314).
- **`SQL_C_DEFAULT`** is the SQL type's default C type, not always `SQL_C_CHAR` (#316). A DATE column then fills a timestamp struct, and a RAW gives its bytes.
- **Diagnostic text** no longer ends in a newline on 9i and later (#364).
- **A session the server ended** (killed, shut down, or a lost connection) reports 08S01 and `SQL_ATTR_CONNECTION_DEAD` true, where it was HY000 and false (#340).

### New features

- **Connecting:**
  - **TNS aliases from tnsnames.ora** (#374). `DBQ=ORCL`, or a `SERVICE` with no `HOST`, is looked up in `$TNS_ADMIN`, `$ORACLE_HOME/network/admin` or `/etc`, with IFILE includes.
    - The entry's TCP / TCPS addresses become the failover list, and its `SERVICE_NAME` or `SID` the target.
    - A TCPS address turns TLS on.
    - An alias that isn't found fails naming the files searched.
  - **Easy Connect in `DBQ`**, as Oracle's ODBC driver takes it: `DBQ=host:port/service`, or `HOST=host:port/service` (#362).
  - **`ORA_SDTZ`** chooses the session time zone: an offset, a region, `OS_TZ` or `DB_TZ` (#358).
- **ODBC escapes and SQLGetInfo:**
  - **The `{fn}` scalar functions** translate to Oracle SQL, and SQLGetInfo advertises them (#301).
  - **The `{INTERVAL}` literal escape** translates (#305).
  - **SQLGetInfo** answers about 75 more info types: the SQL-92 masks, keywords, schema usage and limits (#306, #308).
    - `SQL_DRIVER_VER` is the release version (#310).
    - `SQL_MULT_RESULT_SETS` and `SQL_BATCH_SUPPORT` are answered per release (#312).
- **Parameters:**
  - **Every parameter C type is sent as its value:** `SQL_C_NUMERIC`, the unsigned types, GUID and the interval types were sent as raw bytes (#322).
  - **Character data for a numeric parameter** binds as a locale-free number, so it works when the session's decimal separator is `,` (#354).
  - **ODBC date and timestamp literals given as text** bind as native dates and timestamps, so they work whatever `NLS_DATE_FORMAT` is (#356).
  - **National-character parameters** on a non-Unicode database use the national character set, so an `NVARCHAR2` keeps characters the database charset lacks (#367).
- **Rowsets and positioned operations:**
  - **A truncated row in a rowset** is `SQL_ROW_SUCCESS_WITH_INFO`, and each diagnostic names its row (#369).
  - **SQLSetPos over a whole rowset** runs every row, each failing row with its own status and error (#371).
- **Oracle 8i:**
  - **REF OUT parameters** (#241, part), a NULL one read as NULL (#325);
  - **timestamp-struct parameters** bind as DATE (#318);
  - **describing a prepared query** before it runs, with or without markers (#353);
  - **knowing whether a transaction is open**, for SQLDisconnect (#344).
- **Core API:**
  - **New functions:** `seer_stmt_bind_number_text`, `seer_txn_open`, `seer_db_charset_unicode` and `seer_conn_sdu`.
  - **Time-zone text:** TIMESTAMP WITH TIME ZONE text now ends in its offset, and LOCAL TIME ZONE text is in the session's zone, as in ODBC.

### Fixes

- **Wrong data with no error:**
  - **SQLGetData in `SQL_C_WCHAR` pieces** stopped early: `hello world` came back as `hello ` (#351).
  - **`SQL_C_BIT` parameters on 23ai** were bound as BOOLEAN whatever their `ParameterType` (#327).
  - **SQLPutData** read past the buffer for fixed-size C types, honouring a length they don't have (#323).
- **SQL with a repeated placeholder** before a new one failed with ORA-01008 (#302).
- **10g: the statement cache's hidden cursors caused ORA-01000** on servers with a small `open_cursors` (10g's default is 50) (#337).
- **9i: a CLOB / BLOB whose read fails** fetched as an empty value; it is now the cell's error (#349).

### Tooling

- **CodeQL:** `cpp/path-injection` is excluded with its reason. The only files the driver opens are named by its own caller's environment and config (#376).
- **Code style:** Oracle type numbers in the ODBC type mapping are named constants (#321).
- **Tests:** each fix above has a live check that fails without it. Both suites now hold 160 ODBC and 119 core-API checks on 23ai. The offline suite has 26 unit tests, with a tnsnames.ora reader test, and the fuzz harness covers the new TIMESTAMP WITH TIME ZONE decoder.
- **Homebrew:** the formula points at the 0.4.0 tarball (#300).

- **Live, full matrix green** (`tests/odbc/run-matrix.sh`, lab servers, on this branch at `55d7be1`, the version bump on master `e3ccfff`). The laptop's zone is +01:00, so every session ran off the servers' +00:00 default. Pass / fail / skip:

  | ODBC | 127/0/35 | 142/0/20 | 144/0/18 | 143/0/19 | 153/0/9 | 154/0/8 | 160/0/2 | 160/0/2 |
  | core API | 94/0/18 | 94/0/18 | 93/0/17 | 94/0/16 | 102/0/10 | 108/0/7 | 119/0/2 | 117/0/4 |

  The servers are 8i 8.1.7, 9i 9.2.0.4, 10g 10.2.0.5, 11g XE 11.2.0.2, 18c XE, 21c XE 21.3, 23ai Free, and 26ai (23.26.2) with native network encryption required. Each skip is a gap a release lacks, named with its reason in the suite.
- **Windows, live, under Microsoft's ODBC Driver Manager**, on one Windows 11 (26H2) x64 VM. It used this release's own artifacts from a `release.yml` dry run, against all eight servers above:
  - the x64 and the x86 zip each pass `selftest.ps1` **27/0**, by connection string and by DSN;
  - the installer installs silently, both installed drivers pass `selftest -Installed` **25/0**, and it uninstalls leaving no driver registration or folder.
- **Offline:** 26 unit tests, in a plain and in an ASan + UBSan build.
- **GitHub CI (public tier):** 11g XE, 21c XE and 23ai Free containers, under ASan + UBSan; native and cross Windows builds; macOS. CI's containers run in UTC, where the session-zone check's "no ORA_SDTZ" case equals the server default. Its offset and region cases, and the LOCAL TIME ZONE check, still test the change there.
- **Not validated:** 12.1, 12.2 and 19c against real servers (12.1's wire level is exercised by capping a 21c session); Windows 10, Windows on ARM, and applications other than the test tools; the installer on 32-bit Windows. The tnsnames.ora live check runs only on Linux and macOS.
- **Known limitations:**
  - **Time zones:**
    - a region zone, as the session's or the database's zone, leaves LOCAL TIME ZONE values in the database's zone, with a warning in the log, since its daylight-saving rules aren't on the wire;
    - LOCAL TIME ZONE attributes inside an object are not converted;
    - a session zone changed where the driver can't see it (in a stored procedure) is missed.
  - **tnsnames.ora:** LDAP naming and `sqlnet.ora` settings beyond the file's location are not read.
  - **Waiting on a reference client or seerdb:**
    - SQLDisconnect's open-transaction check on 9i, whose replies don't say (#344);
    - PL/SQL associative arrays on 9i (#254);
    - REF binds on 10g / 11g (#241);
    - package-level PL/SQL record types on 10g / 11g (#193).
  - **Windows:** the installer is **not code-signed**, so SmartScreen may warn before it runs.
  - **DRCP on 11g** is not supported.

### Installing

- **Windows:** run `seerodbc-0.5.0-windows-setup.exe`, or unpack the zip for your application's bitness and run `register.cmd` from an elevated prompt. See `packaging/windows/README.md`.
- **Linux, from source:** `meson setup build && meson compile -C build`, then register `build/src/odbc/libseerodbc.so` (see `packaging/odbcinst.ini.sample`).
- **Fedora:** `packaging/seerodbc.spec` builds from this tag's tarball.
- **macOS:** as Linux, with Homebrew's OpenSSL 3 and unixODBC. The Homebrew formula moves to 0.5.0 once the tag exists, since it pins the tag's tarball.
