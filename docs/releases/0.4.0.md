SeerODBC 0.4.0 brings **Oracle 8i and 9i close to the newer releases**: binds, DML, PL/SQL, LOBs, objects, two-phase commit and Advanced Queuing now work there. It also fills in much of **ODBC conformance**: the catalog functions, cursor names and positioned DML, descriptors, timeouts and statement attributes. And it fixes about forty bugs.

**Upgrade if you use 23ai Free:** Oracle **23.26.4** broke LOB reads, large OUT values and error reporting in 0.3.0 (#285).

### Changes you may notice

None of these needs a code change, but an application could see a difference:

- **Server errors carry a real SQLSTATE** instead of HY000 for everything, for example 23000 for a unique or foreign-key violation, 42S02 for a missing table, 40001 for a serialization failure (#208). A connect that never got a session is **08001**, not 08S01 (#206).
- **A commit the server refuses is an error.** It used to report success while the server had rolled the transaction back. It is now `SQL_ERROR` with 40002 and the ORA number (#185).
- **Bind positions follow the order of appearance on every release.** On 8i and 9i a PL/SQL block used to bind `:N` by its number (#147).
- **Column bindings now last until unbound,** across executes, as ODBC specifies. Before, each execute dropped them (#247).
- **Catalog functions:**
  - **Name arguments:** they honour the `\` search-pattern escape, and the ordinary (non-pattern) arguments of SQLPrimaryKeys, SQLStatistics, SQLForeignKeys and SQLSpecialColumns match literally, so `SEER_A_B` no longer also matches `SEER_AXB` (#276).
  - **SQLStatistics** returns the table's SQL_TABLE_STAT row first (#277).
  - **SQLTables** returns ODBC's catalog, schema and table-type enumerations, where it listed every table (#283).
- **Column sizes:**
  - **Sizes and types match SQLDescribeCol / SQLColAttribute:** SQLColumns, SQLProcedureColumns and SQLGetTypeInfo now report them as those do (#263, #267, #271).
  - **Specific types:** LOB and LONG columns report 2147483647 (#270). RAW(n) is n, and character sizes are in characters (#266).
- **Unsupported attribute values are substituted, with 01S02:**
  - SQL_CONCUR_ROWVER and SQL_CONCUR_VALUES become SQL_CONCUR_LOCK, since the driver can't detect a row changed since the fetch (#295).
  - Keyset-driven and dynamic cursors become static (#227).
- **8i, 9i:** a `double` or `float` binds as the NUMBER that reads back exactly. NaN and the infinities are refused (#164).
- **Core API, 9i:** a two-phase `seer_tpc_begin` needs the new `SeerConnParams.xa`. Logging on with the XA names kept a refused commit's transaction alive (#185).

### New features

- **Oracle 8i (8.1.7)**, which was read-only in 0.3.0:
  - **Statements:** IN binds (#137); DML, DDL and transactions (#138); PL/SQL blocks with IN, OUT and IN OUT parameters, and DML RETURNING (#139).
  - **Data types:** CLOB, BLOB and BFILE columns (#142), and LOBs from RETURNING (#215); object and collection columns (#232), with their LOB attributes (#233), and binds (#236); REF CURSOR OUT and `CURSOR()` columns (#200); PL/SQL associative arrays, IN and OUT (#253); REF IN binds (#242).
  - **Features:** two-phase commit through `SYS.JAVA_XA` (#180); Advanced Queuing, RAW and object payloads, through `DBMS_AQ` (#190, #239).
  - **Catalog:** SQLPrimaryKeys, SQLStatistics and SQLForeignKeys, which failed on 8i's SQL (#274).
- **Oracle 9i (9.2):**
  - **Statements:** one server cursor per statement (#115); array DML with batch errors (#116, #124); describe before execute (#125); DML RETURNING (#126); text and RAW binds past the inline limits (#127, #129); PL/SQL OUT values past 2000 / 4000 bytes (#192); long values as temporary LOBs (#230).
  - **Data types:** TIMESTAMP and INTERVAL binds, and LONG fetch (#116); object and collection columns (#231) and binds (#236); XMLType and REF columns (#237); REF IN and OUT binds (#242, #252); REF CURSOR OUT (#199).
  - **Features:** two-phase commit (#178); Advanced Queuing (#190, #239).
  - **Diagnostics and login:** the error offset and compilation warnings (#117); the key-value login envelope (#131).
- **Oracle 10g / 11g:**
  - **Two-phase commit** (#175, #178).
  - **Advanced Queuing:** RAW, object and array enqueue / dequeue, correlation and consumers (#181, #182, #186, #188, #195).
  - **Binds:** object and collection binds (#191); associative arrays (#194).
- **Connecting:**
  - **Failover:** a HOST address list, tried in turn (#202); each failure names the address and its cause (#204).
  - **Timeouts:** SQL_ATTR_LOGIN_TIMEOUT / CONNECT_TIMEOUT bound each address (#219).
  - **Identification:** the client's OS user is sent in the connect descriptor (#128, #130).
- **ODBC:**
  - **Timeouts and cancel:** SQL_ATTR_QUERY_TIMEOUT (HYT00) (#211), SQL_ATTR_CONNECTION_TIMEOUT (#229), and an out-of-band break where the server takes one (#225).
  - **Statement and connection attributes:** SQL_ATTR_TXN_ISOLATION (#222), SQL_ATTR_MAX_ROWS (#223), SQL_ATTR_MAX_LENGTH and SQL_ATTR_NOSCAN (#249), the cursor type / scrollable / sensitivity attributes (#227), SQL_ATTR_METADATA_ID (#279).
  - **Parameters:** row-wise parameter arrays, bind offsets and SQL_ATTR_PARAM_OPERATION_PTR (#245); SQL_SEER_CLOB / SQL_SEER_BLOB for PL/SQL LOB OUT parameters (#240); SQL_SEER_REF for REF parameters (#256).
  - **Positioned operations:** SQLSetPos honours SQL_ATTR_ROW_OPERATION_PTR (#251). Cursor names (SQLSetCursorName / SQLGetCursorName) and positioned `UPDATE` / `DELETE ... WHERE CURRENT OF` (#290).
  - **Descriptors:** SQLCopyDesc (#292); explicitly allocated descriptors, shareable as several statements' ARD, or an APD (#293).
  - **Catalog:** SQLTablePrivileges and SQLColumnPrivileges (#287).
  - **Metadata:** column metadata from the describe's precision and scale (#260); SQLGetDiagField's row count, dynamic function and origins (#258); SQLGetInfo answers for the common info types (#235), and cursor capabilities that list SQLSetPos and locking (#295).
- **Core API:**
  - **Bindings:** `seer_stmt_bind_ref` / `seer_stmt_bind_ref_out` (#242, #252); `seer_stmt_set_max_rows` (#223).
  - **Metadata:** `seer_stmt_col_octets` (#266).
  - **Connection:** `SeerConnParams.xa` (#185).

### Fixes

- **23ai 23.26.4: LOB reads, large OUT values and error reporting failed** with protocol errors. The release fills network fragments to a size no earlier one used, and the driver took the first fragment for the whole reply (#285).
- **A refused commit reported success** on 9i, 10g and 21c, though the server had rolled it back (#185).
- **9i:**
  - **any statement with a non-ASCII character in its SQL hung**: the length was sent in bytes, and 9.2 reads it in characters (#141);
  - a query that failed while fetching (e.g. ORA-01476) had no error text (#160), and now and then an error came back with a stray or the previous call's text, its ORA number and SQLSTATE lost (#296);
  - a column described with size 0, such as `TO_NUMBER(NULL)`, failed the query (#157);
  - a `CURSOR()` column read as garbage (#197).
- **8i:**
  - a query with around 200 or more columns failed and left the session out of step (#154);
  - a NULL VARCHAR2 from a table read as an empty string (#155);
  - a UROWID holding a physical rowid read in the `*` base64 form instead of as that ROWID (#143).
- **10g and later:**
  - a PL/SQL block failed with a protocol error when an OUT parameter came back NULL (#150);
  - a long logical UROWID (an index-organized table's, past 252 bytes) failed with a bogus ORA-01403 (#145);
  - REF CURSORs leaked server cursors (#199).
- **Statement cache:**
  - a cached cursor was re-run with its old describe for binds of other types (#163);
  - a query failed with a protocol error after another session retyped its table (#213);
  - a failed cached statement was retried on any error, so a deadlock waited twice (#213).
- **18c DRCP: pooled connections were closed** at the first packet; each packet is now written in one send (#114).
- **An unopenable BFILE** read back empty with no error on 9i and later; it is now the server's error when the cell is read (#165).
- **Connect:** `EXPIRE_TIME` with an empty `TLSCA=` used freed memory, and leaked otherwise (#218).
- **ODBC:** SQLDescribeParam described parameters the statement doesn't have (#281).

### Tooling

- **CI** runs only the jobs a change needs (#111). The open CodeQL quality alerts are cleared (#113).
- **The live test suites:**
  - **One core-API suite** runs on every tier, and the ODBC suite with it, each skipping a known gap by release with a reason (#112, #118, #161, #170, #174).
  - **8i reply parsing:** a unit test pins that a status behind the RPA is read on, never taken as success (#177).
  - **New offline tests** cover the 9i error text and the `WHERE CURRENT OF` scan.
- **Docs:** describe 8i and 9i as they are now (#255, #261).

- **Live, full matrix green** (`tests/odbc/run-matrix.sh`, lab servers, on master `7242c2e`: this release's code but for the version number and the smoke tool's 8i check, #297). Every tier now runs both suites, the ODBC suite and the core API's (pass / fail / skip):

  | core API | 91/0/20 | 93/0/18 | 93/0/17 | 94/0/16 | 101/0/10 | 107/0/7 | 118/0/2 | 116/0/4 |

  The servers are 8i 8.1.7, 9i 9.2.0.4, 10g 10.2.0.5, 11g XE 11.2.0.2, 18c XE, 21c XE 21.3, 23ai Free, and 26ai (23.26.2) with native network encryption required (AES256 + SHA256). Each skip is a gap a release lacks, named with its reason in the suite.
- **Oracle 23.26.4** (#285): both suites pass on a local container of CI's `gvenzl/oracle-free:23-slim` image at 23.26.4, by digest, and in CI, which now runs that image.
- **Windows, live, under Microsoft's ODBC Driver Manager** on one Windows 11 (26H2) x64 VM, using this release's own artifacts from a `release.yml` dry run, against all eight servers above:
  - the x64 and the x86 zip each pass `selftest.ps1` **27/0**, by connection string and by DSN;
  - the installer installs silently, both installed drivers pass `selftest -Installed` **25/0**, and it uninstalls leaving no driver registration or folder;
  - 8i is in the self-test for the first time; its wide-API smoke check reads `CHR(196)`, since 8.1.7 has no `UNISTR` (#297).
- **Offline:** 24 unit tests, in a plain and in an ASan + UBSan build.
- **GitHub CI (public tier):** 11g XE, 21c XE and 23ai Free (23.26.4) containers, under ASan + UBSan; native and cross Windows builds; macOS.
- **Not validated:** 12.1, 12.2 and 19c against real servers (12.1's wire level is exercised by capping a 21c session); Windows 10, Windows on ARM, and applications other than the test tools and .NET's `System.Data.Odbc`; the installer on 32-bit Windows.
- **Known limitations:**
  - **Binds no reference client can show, or that wait on seerdb:**
    - a REF OUT parameter on 8i, waiting on seerdb for the form (#241);
    - PL/SQL associative arrays on 9i, which no client binds in the dialect SeerODBC speaks to 9.2 (#254);
    - package-level PL/SQL record types on 10g and 11g, likewise (#193).

    Each issue gives a workaround.
  - **ODBC:**
    - an explicitly allocated descriptor carries records only, its array size and bind type staying the statement's attributes;
    - SQL_DESC_BASE_COLUMN_NAME is the select-list label, since the describe names no base column.
  - **Windows:** the installer is **not code-signed**, so SmartScreen may warn before it runs.
  - **DRCP on 11g** is not supported: 11g's pooled server needs a client form SeerODBC doesn't implement.

### Installing

- **Windows:** run `seerodbc-0.4.0-windows-setup.exe`, or unpack the zip for your application's bitness and run `register.cmd` from an elevated prompt. See `packaging/windows/README.md`.
- **Linux, from source:** `meson setup build && meson compile -C build`, then register `build/src/odbc/libseerodbc.so` (see `packaging/odbcinst.ini.sample`).
- **Fedora:** `packaging/seerodbc.spec` builds from this tag's tarball.
- **macOS:** as Linux, with Homebrew's OpenSSL 3 and unixODBC. The Homebrew formula moves to 0.4.0 once the tag exists, since it pins the tag's tarball.
